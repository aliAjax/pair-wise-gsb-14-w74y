# 出租车燃油附加费联动批次

- 行业：城市出租车 / 石油联动
- 技术栈：Vue3、Vite、TypeScript、Pinia、Naive UI
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 一条执行批次如何串起四本账

油价备案、附加费标准、计价器下发、乘客告示各自记账，再由“执行批次”串成同一条链：

1. **备案即重算**：92号汽油备案价变更后立即登记备案与联动分档标准，生成完整批次（快照含备案价、附加费、分档、生效日）。所有未确认（未生效）批次**立即失效**并由新批次承接重算；**已生效班次保留当时快照**，不受影响。
2. **发布只放行先到者**：两名运营员并发发布时，先到者持有发布锁，后来者被拒并写审计；持锁后向全部计价器、告示统一下发。下发失败（版本核对失败或通道故障）回到完整批次重试，已确认回执不重算。
3. **离线留待回连**：计价器/告示离线时下发与回执挂起；回连后按**设备号 + 批次号**核对回执。同一回执号或同一设备的重复回执幂等忽略，不重复计入；回执附加费与批次快照不一致、设备号不在花名册、批次号对不上，一律列入**异常设备单列**。
4. **全部一致才切换**：全部计价器和乘客告示回传附加费均与快照一致后才允许切换；切换是原子动作，新批生效即冻结快照，旧批转历史。已生效批次之后到达的回执只登记异常，**不能改写已生效结果**。
5. **旧附加费按生效日补档**：历史班次按当时生效的旧附加费补档，台账缺班次则补不全，批次停在**待核**，不允许切换；补齐对应日期台账后继续。
6. **同一结论三处读取**：总览卡片、批次详情、审计页顶部结论全部由同一个纯函数 `batchConclusion` 从同一份 Pinia 状态推导；审计流水只追加、不改写。

数据默认保存在浏览器 localStorage，审计页可一键恢复演示种子。
